# Contributing to Kiwi CI

Kiwi CI is a single-binary Go CI/CD engine: a CLI, a control plane, and a
runner in one program. Contributions are welcome in all three areas, plus
documentation and the pipeline language.

## Ground rules

- The repo must always build: `go build ./...` and `go vet ./...` pass.
- Existing tests must pass: `go test ./...`.
- Go source stays small and auditable. Every non-generated source file is
  intentionally short; split files rather than growing them.
- No new third-party dependencies without a written justification. The
  runtime dependency set is currently `pgx/v5` (PostgreSQL) and
  `yaml.v3` (pipeline parsing).
- Every dependency in the Go build list must carry an allowlisted
  license: Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC, MPL-2.0,
  PostgreSQL, Unlicense, or 0BSD. `make license-check` scans
  `go list -m all` (including transitive modules and replaced modules)
  and fails on a missing or non-allowlisted license. After any
  dependency change run `make license-notice` and commit the regenerated
  `NOTICE`; CI fails on NOTICE drift.
- Documentation claims must match the code. When you change behavior,
  update the relevant file under `docs/` and regenerate `FILE_MAP.md`.

## Development setup

```bash
git clone https://github.com/Bel-Consulting-OU/kiwi-ci.git
cd kiwi-ci
go build ./cmd/kiwi
./kiwi doctor
```

Go 1.23 or later is required.

## Workflow

1. Open an issue describing the bug or feature, or comment on an
   existing one.
2. Create a branch from `main`.
3. Make the change, including tests where practical.
4. Run the CI gates locally. The Makefile targets mirror the Woodpecker
   lanes one-to-one:

   ```bash
   test -z "$(gofmt -l .)"   # format gate
   make lint           # go vet ./...
   make test-unit      # go test ./...
   make test-race      # go test -race -shuffle=on ./...
   make test-adversarial
   make fuzz           # 10s per fuzz target
   make schema-check   # pipeline schema + FILE_MAP.md freshness
   make cross
   make docs-check
   make license-check
   make repro-build
   make staticcheck    # staticcheck v0.8.1
   make govulncheck    # govulncheck v1.8.0, needs network
   make coverage       # writes coverage.out and prints the total
   make coverage-floor # fails under KC_MIN_COVERAGE (default 60)
   ```

   The real-PostgreSQL lane is env-gated: point it at any throwaway
   database (each test creates and drops its own `kiwi_it_<random>`
   schema) and run

   ```bash
   make integration    # KIWI_TEST_POSTGRES_URL must be set
   ```

   Without `KIWI_TEST_POSTGRES_URL` (and in `-short` mode) the
   integration tests skip, so `make test-unit` stays hermetic. The CI
   lane name is `integration-postgres` in
   `.woodpecker/integration-coverage.yml`.

5. If you changed Go files, run `go run ./cmd/filemap` and commit the
   regenerated `FILE_MAP.md`.
6. Open a pull request using the pull request template.

## Security-sensitive changes

Changes to `internal/executor`, `internal/policy`, `internal/safefs`,
`internal/runnerpki`, `internal/server` (leases, OIDC, secrets), or
`internal/storage` require extra care:

- Keep deny-by-default behavior: anything not explicitly granted by the
  capability policy must stay denied.
- Never weaken the untrusted pipeline floor (no native execution, no
  network egress, no secrets, no OIDC for untrusted runs).
- Never persist raw lease tokens or secret values.
- Add regression tests for every security property you touch.

Report vulnerabilities privately instead of opening a public issue; see
[SECURITY.md](SECURITY.md).

## Code style

- `gofmt` formatting, no comments that restate the code.
- Errors are wrapped with context: `fmt.Errorf("step: %w", err)`.
- Package comments describe the package's contract.
- No emoji, no marketing language, in code or docs.

## Documentation

- Pipeline language changes go in `docs/pipeline-reference.md` and
  `.kiwi/schema.json` (the two are pinned together by a test).
- Operator-facing behavior goes in the relevant `docs/` file.
- `FILE_MAP.md` is generated by `cmd/filemap`; do not edit it by hand.

## Community

Be respectful. The project follows the
[Contributor Covenant](CODE_OF_CONDUCT.md). Maintainers will remove
comments and reject contributions that do not.
